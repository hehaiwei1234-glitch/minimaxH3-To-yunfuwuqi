## ★ 最高优先级：先读完这一节，再做任何事（新聊天必读）

**这一节高于一切：高于聊天里的临时安排、高于说明书里的其他描述、高于“先记下来再说”的冲动。与它冲突时，以它为准。这是 hh 使用 Claude Pro 做这件事的目的所在。**

### 1. 这份文档为什么存在

hh 在做 AI 短剧生产线，视频由 H3 生成。H3 有自己的脾气：很多写法按常识没有任何毛病，H3 却理解不了、做不出来或做歪（例如：写“没有镜子”，镜子照样出现；写“一只手从画面边缘伸进来”，那只手就变成无主的手）。

**这份文档唯一的价值：把 H3 的这些规律归纳成一套通用的、可靠的写法，让以后任何一个新聊天里的 Claude 写剧本和制作稿时，直接按 H3 的方式写，一次就尽量写对**，而不是每个片段出了问题再各个击破。

### 2. 里面记什么（只记这三类）

1. **H3 的通用规律（最重要）**：H3 对提示词、开场图、声音的反应方式。一条规律必须能解释多个不同的案例；每条写成：**规律｜依据（合并了哪些案例、样本数 n）｜把握程度｜该怎么写**。
2. **影响写稿的插件事实**：要短，只留会改变“怎么写”的。
3. **待验证的假设**：单独放、要短；不混进规律里。

### 3. 不记什么（这些就是“屎山”的来源）

- 单个片段发生了什么的流水账；只在一个片段里出现一次的现象。除非它是某条通用规律的例子，那样只在那条规律的“依据”里留一笔。
- Claude 自己的失误记录、道歉、过程感想（写进 `docs/项目进度与实验记录.md`，不写进这里）。
- 没验证的猜测不得写成规律。
- 重复的内容：新证据并入原来那一条，**不新增条目**。

### 4. 怎么更新（流程，必须照做）

1. 有新结论时，**先在聊天里向 hh 列出问题点**，逐条标明归属：① H3 的理解问题（最有价值）② Claude 自己的缺陷 ③ 插件软件本身；写明证据等级和样本数 n。
2. 把单点现象**归纳成通用规律**。门槛：能解释多个不同的案例，或至少有 3 次一致的观察；达不到的只进“待验证”。
3. **hh 点头之后才能改这份文档，没有点头不准改。** 合并时优先并入已有条目；一轮分析结束后一次性改，不要每回复一次就改一次。
4. 改完自查：有没有把流水账带进来？有没有重复？文档有没有无谓变长？
5. 归档手册 `docs/H3手册.md` 只作查证据用，不再往里添新条目；是否整理它，先问 hh。

## 二、影响写稿的插件事实（只留会改变“怎么写”的）

- **成片是各任务按顺序硬切拼接，没有转场**（17 段相加 109.419 秒，成片 109.455 秒，O40）。每个任务要自己把场景交代清楚。
- **英语一句台词 ≤7 个单词。** 插件按每秒 2 个英语单词估算，格式检查会卡对白时间（F7）。时长按 17k+5 帧取整，5 秒实际 5.167 秒，6 秒实际 6.583 秒。**有台词的任务保留 H3 的原始尾部（比计划长 0.17–0.58 秒），没台词的任务裁成刚好 5.0 / 6.0 秒（第 3 集 14 个片段），所以成片总长比计划长。**
- **追加后续稿：** `style`、同名素材、同名角色必须逐字相同，否则整批被拒（F11）；写成 `generate` 的素材每次都重新生成，想沿用旧人物要写 `source`（F12）。
- **“承接前段”（`depends_on_previous`）：** 把上一段最后一帧交给下一个开场图做位置参考。界面里没有开关，只能写在稿子里；缺省是开；**重做一段，会连带重做后面承接它的段落**（F13）。**机制（源码）：关着时，每个任务的开场图在一开始就各自独立生成，不看上一个视频——所以同一场景同一批人的相邻任务，姿势、站位、衣着可能互相对不上（我们的稿子长期把它写成关着）；打开时，插件要等上一个任务的视频被采用，再取它的倒数第二帧（时长减 0.08 秒）当“前段状态”参考图，只参考位置、道具、环境，身份仍由人物肖像固定；这张图占一个参考图位（参考图总数上限 8 张），上一个任务一旦被重做就作废。写法：同场景、同一批人的相邻任务全部打开；换地点、换人、插镜头之后关闭。实测（新剧第二版）：同场景同一批人、承接前段打开的 3 对相邻任务，人物姿势、衣着、房间、桌上的东西全部接上（3/3，没有出现“站着变躺着”这类对不上）。****实测作用（第 3 集 8 次承接）：同一批人、同一场戏的相邻两段，姿势、站位、光线接得上（5/5）；1 次同人同房间但镜头从广角换成侧面特写，房间大体接上；接不上的 2 次，都是“另一个人被移出画面、改成单人＋视线看画外”的连续段，房间里冒出原来没有的门或窗帘（n=2，原因不明）。不承接的段落，只要用同一张场景素材并写固定布局句，房间也基本一致（4 段）。结论：承接前段保的是姿势和位置的连续，不是房间一致。**

- **任务时长和台词条数（源码）：** 单个任务时长 0.25–15 秒，生成时长 2–15 秒；一个任务的台词是一个列表，可以有多句、多个说话人（每个说话人单独设声音），格式检查按“每句自然语速预算＋句间 0.12 秒＋开头 0.1 秒＋句尾至少 0.65 秒”算总长。所以 10–15 秒的长任务、一个任务里两个人来回说话，在格式上都允许；“一个任务一句话”是我们为了稳妥自己定的，不是插件限制。
- **种子（源码＋实测）：** 稿子里每个任务写的 `seed` 只管**视频**，不传给开场图；不写就用界面里的全局种子。开场图的种子由生图工作流决定（源码默认用工作流里写死的数）。**实测：同一段开场图文字、同样的参考图、都不承接前段，只换视频种子，3/3 开场图完全不同（构图、人物位置，有一个连房间都不同）；既然换视频种子在源码里不影响开场图，说明开场图每次生成本来就会变。全集用同一个视频种子，那一集里照样有一个任务整张画成了另一间房。结论：种子管不住画面一致，不用统一种子；开场图不对，重做这一个任务就会换一张新的。**
- **承接前段的相邻任务，接缝会像“跳切”：** 承接前段且景别相同的两个任务，上一个的最后一帧和下一个的第一帧几乎一样（41 个接缝里 3 个，画面差异 8–20；普通换镜头的接缝是 26–80）。直接拼接时看起来是同一个镜头里画面小跳一下，剪掉两端空等之后更明显（只是量出了这三处，是否就是 hh 觉得“跳”的那些，没核对）。要承接就让下一个任务换一个景别或换一个人，别原样接。
